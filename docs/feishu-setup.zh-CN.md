# 飞书配置

[English](feishu-setup.md)

Nod 用**你自己的**飞书机器人给每个 PR 发一张卡片，并通过长连接接收卡片上「直接通过」按钮的点击，所以不需要公网地址。

> **为什么要用自己的应用？** 飞书长连接会把每次按钮点击只交给连接到这个应用的其中一个程序。如果几个人的 Nod 用同一个应用，彼此的点击会落到别人的电脑上。所以每人建一个应用，大约 5 分钟。

## 1. 创建应用

1. 打开开发者后台：<https://open.feishu.cn/app>（Lark 国际版：<https://open.larksuite.com/app>）。
2. 点 **创建企业自建应用**。名称和图标随意，例如「代码审查」。描述写短一点，比如「PR 自动审查」，它会显示在聊天窗口顶部。
3. 进入 **添加应用能力 → 机器人**，添加机器人能力。

## 2. 权限

在 **权限管理** 里开通 **以应用的身份发消息**（`im:message:send_as_bot`），其他权限都不需要。更新机器人自己发出的卡片也用这个权限。

## 3. 配置 Nod 并先连上一次

开发者后台只有在有程序连着的时候，才能把订阅方式选成长连接，所以要先让 Nod 连上：打开 Nod 的「设置 → 通知」（第一次使用时是引导的第 3 步），通知方式选「飞书卡片」，填入 App ID、App Secret（在「凭证与基础信息」里）和接收人，点「保存」。保存后 Nod 会马上连上飞书，保持它运行，下一步要用。

**接收人**（卡片发给谁）可以写成下面任意一种：

| 写法 | 去哪里找 |
|---|---|
| `email:you@company.com` | 你的飞书登录邮箱（应用要能看到你，见第 5 步） |
| `open_id:ou_…` | 每个应用各不相同的用户 ID；在 API 调试台用这个应用调用「获取用户信息」可以看到 |
| `union_id:on_…` / `user_id:…` | 同一企业各应用通用的用户 ID / 你的员工 ID |

`open_id`、`union_id`、`user_id` 更严格：点击者的 ID 必须对得上才会受理。用 `email` 时，只受理发到你和机器人私聊里的那张卡片上的点击。

## 4. 用长连接接收卡片回调

进入 **事件与回调 → 回调配置**：

1. 订阅方式选 **使用长连接接收回调**，点保存。只有 Nod 在运行且没有暂停时才能保存成功。
2. 点 **添加回调**，勾选 **卡片回传交互**（`card.action.trigger`）。

## 5. 发布

进入 **版本管理与发布 → 创建版本**，可用范围只选你自己。很多企业里，只对所有者（以及最多 5 名其他成员）可用的应用发布时免审核。然后点 **发布**。

## 6. 验证

在「设置 → 通知」里点「发一条测试通知」，你应该会收到一张「连通测试」卡片。

## 排障

- **环境检查提示应用凭证被拒绝**：App ID 或 App Secret 填错了，或者在后台重置过密钥。
- **测试卡片发不出去**：可能是应用还没发布、你不在可用范围里、没开通「以应用的身份发消息」权限，或者接收人填错了。报错里会带上飞书返回的原因。
- **点按钮弹出错误提示**：Nod 没在运行或已暂停（看托盘图标），或者有别的程序也连着这个应用的长连接，抢走了这次点击。一个应用只能有一个程序连。
- **卡片不更新**：这张卡片是旧版本或别的应用发的；新卡片都会原地更新。
- **Lark 国际版**：把 `notify.feishu.domain` 设为 `"https://open.larksuite.com"`。
